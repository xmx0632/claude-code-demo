# 本地需求管理

> 基于 Markdown 的轻量级需求管理，与 SDLC 框架深度集成

---

## 快速开始

### 创建新需求

```bash
# 1. 复制模板
cp TEMPLATE.md backlog/REQ-003-我的功能.md

# 2. 编辑需求文件
# 填写需求描述、验收标准、技术要点

# 3. 在 Claude Code 中处理
# "处理需求 REQ-003"
```

---

## 目录说明

| 目录 | 用途 |
|------|------|
| `backlog/` | 待处理需求池 |
| `active/` | 正在开发的需求 |
| `completed/` | 已完成的需求归档 |

---

## 需求状态

| 状态 | 图标 | 说明 |
|------|------|------|
| draft | 📝 | 草稿，信息不完整 |
| backlog | 📋 | 待处理，已评审 |
| active | 🔄 | 进行中 |
| done | ✅ | 已完成 |
| blocked | 🚫 | 阻塞中 |
| cancelled | ❌ | 已取消 |

---

## SDLC 集成

需求文件内置 **SDLC 进度追踪表**，自动记录各阶段状态：

```markdown
| 阶段 | 状态 | 开始日期 | 完成日期 | 产出物 |
|------|------|----------|----------|--------|
| 需求分析 | ✅ 完成 | 2026-03-15 | 2026-03-15 | REQ-001.md |
| 架构设计 | 🔄 进行中 | 2026-03-15 | - | - |
```

---

## 命名规范

```
REQ-NNN-简短标题.md

示例:
REQ-001-用户登录功能.md
REQ-002-数据导出功能.md
REQ-003-API性能优化.md
```

## 最佳实践

1. **一个需求一个文件** - 保持粒度适中
2. **及时更新状态** - 每完成一个阶段就更新
3. **关联相关需求** - 在"关联资源"中记录依赖
4. **归档已完成** - 移动到 completed/ 保持 backlog 整洁
