# 项目宪法 (Constitution)

> 顶层指导文档，定义项目的基本原则和约束，跨所有阶段生效。

**最后更新**: 2026-03-15

---

## 技术原则

### 架构约束

- [ ] **模块化设计**: 系统应采用模块化架构，各模块职责单一
- [ ] **API 优先**: 所有功能必须通过定义良好的 API 暴露
- [ ] **无状态服务**: 服务层应设计为无状态，支持水平扩展
- [ ] **数据隔离**: 每个模块管理自己的数据，避免跨模块直接访问数据库

### 代码规范

- [ ] **TypeScript 优先**: 所有新代码必须使用 TypeScript
- [ ] **测试覆盖**: 核心业务逻辑必须有单元测试
- [ ] **文档注释**: 公共 API 必须有 JSDoc/TSDoc 注释
- [ ] **错误处理**: 必须使用统一的错误处理机制

### 安全要求

- [ ] **输入验证**: 所有外部输入必须验证和清理
- [ ] **敏感数据**: 密码、密钥等必须加密存储
- [ ] **权限检查**: 每个操作必须检查用户权限
- [ ] **审计日志**: 敏感操作必须记录审计日志

---

## 业务约束

### 数据规则

- [ ] **数据所有权**: 每条数据记录必须有明确的归属
- [ ] **软删除**: 默认使用软删除，保留历史记录
- [ ] **版本控制**: 关键业务数据需要版本控制
- [ ] **数据备份**: 每日自动备份，保留 30 天

### 业务流程

- [ ] **审批机制**: 关键操作需要审批流程
- [ ] **幂等性**: 重复操作应产生相同结果
- [ ] **可追溯**: 每个业务状态变更必须有记录

---

## 质量门禁

### 代码提交前

- [ ] 代码格式化检查通过
- [ ] 静态分析无错误
- [ ] 单元测试通过
- [ ] 覆盖率不低于 80%

### 合并到主分支前

- [ ] 代码审查通过
- [ ] 集成测试通过
- [ ] 性能测试无回归
- [ ] 安全扫描无高危漏洞

---

## 使用方式

在 Claude Code 中执行任何 SDLC 阶段时，AI 应该：

1. 读取本文档，了解项目约束
2. 检查相关原则是否适用
3. 在生成代码/文档时遵守这些约束
4. 如果需要新增约束，更新本文档

```markdown
<!-- 在阶段输出中引用 -->
## 遵循的宪法条款
- 技术原则: 模块化设计, API 优先
- 安全要求: 输入验证, 权限检查
- 质量门禁: 单元测试通过
```
