# Bug 修复场景

## 场景描述
适用于线上问题快速修复，包括问题分析、修复实现和验证部署。

## 触发条件
- 意图包含关键词: "修复"、"fix"、"bug"、"issue"

## 执行流程

```
[开始]
   │
   ▼
[Bug 分析] ──▶ [Bug分析报告.md]
   │            ├─▶ 问题定位
   │            ├─▶ 根因分析
   │            └─▶ 影响评估
   │
   ▼
[修复实现]
   │
   ▼
[单元测试]
   │
   ▼
[回归测试] ─▶ [修复验证报告.md]
   │
   ▼
[部署上线]
```

## 必需文档 (2个)

1. **Bug 分析报告** (Bug-Analysis.md)
   ```markdown
   # Bug 分析报告

   ## Bug 信息
   - Bug ID: BUG-001
   - 标题: 用户登录超时
   - 严重程度: 高/中/低
   - 报告人: xxx
   - 发现时间: 2026-03-19

   ## 问题描述
   - 复现步骤
   - 实际结果
   - 预期结果

   ## 根因分析
   - 问题代码: AuthService.java:145
   - 根本原因: 缓存未正确失效

   ## 影响评估
   - 影响范围: 登录功能
   - 影响用户: 所有用户
   - 紧急程度: 高

   ## 修复方案
   - 修复代码: 修改缓存失效逻辑
   - 回归范围: 登录相关功能
   ```

2. **修复验证报告** (Fix-Verification.md)
   ```markdown
   # 修复验证报告

   ## 修复信息
   - Bug ID: BUG-001
   - 修复提交: abc123
   - 修复人员: xxx
   - 修复时间: 2026-03-19

   ## 验证结果
   - 单元测试: ✅ 通过
   - 回归测试: ✅ 通过
   - 复现测试: ✅ 已修复

   ## 部署信息
   - 部署环境: 测试环境
   - 部署时间: 2026-03-19 15:00
   - 回滚方案: revert abc123
   ```

## 质量门禁

- [ ] Bug 根因已确认
- [ ] 修复方案已评审
- [ ] 回归测试已通过
- [ ] 部署回滚方案已准备

## 预计时间

- 简单 Bug: 1-4 小时
- 中等 Bug: 4-8 小时
- 复杂 Bug: 1-2 天
