# 遗留项目维护场景

## 场景描述
适用于现有项目的功能维护和优化，跳过需求分析和架构设计阶段，直接进入技术实现。

## 触发条件
- 项目包含 `pom.xml` 或 `package.json`
- 存在源代码目录

## 执行流程

```
[开始]
   │
   ▼
[需求评估] ──▶ [变更需求.md]
   │
   ▼
[影响分析]
   │
   ▼
[技术方案] ──▶ [变更设计.md]
   │          ├─▶ [API变更.md] (如需要)
   │          └─▶ [数据变更.md] (如需要)
   │
   ▼
[代码实现]
   │
   ▼
[回归测试] ──▶ [测试清单.md]
   │
   ▼
[部署上线]
```

## 必需文档 (3个)

1. **变更需求** (Change-Request.md)
   - 变更描述
   - 影响范围
   - 风险评估

2. **变更设计** (Change-Design.md)
   - 代码变更
   - 数据库变更
   - API 变更
   - 兼容性分析

3. **测试清单** (Test-Checklist.md)
   - 回归测试项
   - 新功能测试项
   - 性能验证项

## 可选文档

- 技术方案文档
- 迁移指南

## 质量门禁

- [ ] 变更影响已评估
- [ ] 回归测试已定义
- [ ] 向后兼容已验证
- [ ] 回滚方案已准备

## 预计时间

- 小型变更: 1-3 天
- 中型变更: 3-7 天
- 大型变更: 1-2 周
