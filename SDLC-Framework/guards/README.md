# 质量约束 (Guards)

SDLC Framework 包含三个质量约束智能体，用于在开发过程中自动检查和提醒。

## 约束类型

### 1. 安全约束 (security.md)

**关注领域**: 认证授权、输入验证、数据加密、漏洞防护

**触发场景**:
- 涉及用户输入处理
- 涉及 API 接口
- 涉及认证授权
- 涉及敏感数据处理

**检查清单**:
- [ ] 输入验证
- [ ] 权限检查
- [ ] SQL 注入防护
- [ ] XSS 防护
- [ ] 密码/密钥加密
- [ ] 日志脱敏

### 2. 性能约束 (performance.md)

**关注领域**: API 响应时间、数据库查询、缓存策略、前端性能

**触发场景**:
- 涉及数据库查询
- 涉及大量数据处理
- 涉及 API 响应时间要求
- 涉及前端渲染性能

**性能基准**:
- API 响应时间: P99 < 500ms
- 数据库查询: < 200ms
- 前端 LCP: < 2.5s

**检查清单**:
- [ ] 避免 N+1 查询
- [ ] 使用索引
- [ ] 实现缓存
- [ ] 分页查询
- [ ] 懒加载组件

### 3. 基础设施约束 (infra.md)

**关注领域**: 部署配置、监控告警、资源限制、CI/CD

**触发场景**:
- 涉及新服务/模块部署
- 涉及容器化配置
- 涉及监控告警
- 涉及 CI/CD 流程

**检查清单**:
- [ ] Dockerfile 多阶段构建
- [ ] 非 root 用户运行
- [ ] 资源限制配置
- [ ] 健康检查端点
- [ ] Prometheus 指标暴露
- [ ] 结构化日志输出

## 使用方式

### 代码审查时

```bash
# 执行代码审查时自动应用约束
/sdlc-code-review
```

### 手动触发

```bash
# 安全审查
对 src/auth/ 目录执行安全审查

# 性能分析
分析 src/api/products/ 的性能瓶颈

# 基础设施检查
检查部署配置是否符合规范
```

### 在 SDLC 阶段中

约束智能体会在以下阶段自动触发：

| 阶段 | 触发的约束 |
|------|-----------|
| 架构设计 | Security, Performance |
| 代码开发 | Security, Performance |
| 测试 | Performance |
| 部署 | Security, Infra |

## 质量门禁

### 新项目场景

- [ ] 安全扫描无高危漏洞
- [ ] API 响应时间达标
- [ ] 部署配置完整

### 遗留项目维护场景

- [ ] 变更安全影响已评估
- [ ] 性能回归测试通过
- [ ] 部署回滚方案已准备

### Bug 修复场景

- [ ] 修复无安全副作用
- [ ] 无性能退化
- [ ] 部署验证通过
