## 反馈分类

### 类型 A: 规范 → 实现缺口

**特征**: 规范写清楚了，但实现跑偏了

**根本原因**:
- 开发者没仔细看规范
- 规范太复杂，难以理解
- 缺少自动验证

**改进方向**:
- 强化质量门禁
- 添加自动检查
- 简化规范表达

### 类型 B: 意图 → 规范缺口

**特征**: 需求讨论时漏了细节，规范没覆盖

**根本原因**:
- 需求收集不完整
- 边界条件没考虑
- 异常处理遗漏

**改进方向**:
- 优化需求引导模板
- 添加边界条件检查清单
- 强化异常场景覆盖

### 类型 C: 角色协作缺口

**特征**: 角色之间信息传递丢失

**根本原因**:
- 角色交接不明确
- 文档分散，难以追溯
- 责任边界模糊

**改进方向**:
- 添加角色交接检查点
- 建立统一的文档索引
- 明确各角色责任边界

## 使用方式

### 发现 Bug 时

1. **定位类型**: 判断是 A/B/C 哪种缺口
2. **记录反馈**: 使用 `templates/BUG-REFLECTION.md` 模板
3. **更新框架**: 修改相关的 Constitution/Steering Docs
4. **归档记录**: 在本文件的表格中添加记录

### 定期评审

- **频率**: 每两周
- **内容**: 回顾所有反馈记录，识别共性问题
- **输出**: 框架改进计划
