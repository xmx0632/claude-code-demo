## 问题一：Flyway SQLite 依赖版本缺失

### 问题 1: Flyway SQLite 依赖缺少版本号

**错误信息：**
```
[ERROR] 'dependencies.dependency.version' for org.flywaydb:flyway-sqlite:jar is missing. @ line 57, column 21
```

**原因：**
在 `pom.xml` 中添加了 `flyway-sqlite` 依赖，但没有指定版本号。Spring Boot Parent 的依赖管理中没有包含这个特定的数据库扩展包。

**解决方案：**
1. 移除 `flyway-sqlite` 依赖（阿里云镜像不包含此包）
2. 只使用 `flyway-core` 即可支持基本的数据库迁移功能

**修改文件：** `backend/pom.xml`

**修改前：**
```xml
<dependency>
    <groupId>org.flywaydb</groupId>
    <artifactId>flyway-core</artifactId>
</dependency>
<dependency>
    <groupId>org.flywaydb</groupId>
    <artifactId>flyway-sqlite</artifactId>
    <!-- 缺少 version -->
</dependency>
```

**修改后：**
```xml
<dependency>
    <groupId>org.flywaydb</groupId>
    <artifactId>flyway-core</artifactId>
</dependency>
<!-- 移除 flyway-sqlite -->
```

## 问题二：Java 版本不兼容

### 错误信息
```
[ERROR] Failed to execute goal org.apache.maven.plugins:maven-compiler-plugin:3.11.0:compile
(default-compile) on project library: Fatal error compiling: 无效的标记: --release
```

### 环境信息
```
java version "1.8.0_231"
Java(TM) SE Runtime Environment (build 1.8.0_231-b11)
Java HotSpot(TM) 64-Bit VM (build 25.231-b11, mixed mode)

Apache Maven 3.6.3
Java version: 1.8.0_231, vendor: Oracle Corporation
Default locale: zh_CN, platform encoding: UTF-8
OS name: "Mac OS X", version: "10.16", arch: "x86_64", family: "mac"
```

### 原因分析
1. 项目使用 Spring Boot 3.2.0，要求 JDK 17+
2. 当前系统使用的是 JDK 8
3. Maven 编译器插件尝试使用 `--release` 参数（JDK 9+ 特性）

### 解决方案

#### 方案 A：升级 JDK 到 17+（推荐）

**优点：**
- 使用最新技术栈
- 更好的性能和安全性
- 代码无需修改

**步骤：**
1. 下载并安装 JDK 17
2. 配置 JAVA_HOME 环境变量
3. 保持 Spring Boot 3.2.0 和 `jakarta.*` 包

**macOS 安装示例：**
```bash
# 使用 Homebrew 安装
brew install openjdk@17

# 设置环境变量
echo 'export JAVA_HOME=$(/usr/libexec/java_home -v 17)' >> ~/.zshrc
source ~/.zshrc

# 验证
java -version
```

#### 方案 B：降级 Spring Boot 版本

**优点：**
- 无需安装新 JDK
- 适合旧项目维护

**缺点：**
- 失去新特性
- 需要修改大量代码

**步骤：**
1. 将 Spring Boot 降级到 2.7.18（支持 JDK 8）
2. 将所有 `jakarta.*` 包改为 `javax.*`
3. 设置 `java.version=8`

**修改文件：**
- `backend/pom.xml`
- `backend/src/main/java/com/example/library/entity/*.java`
- `backend/src/main/java/com/example/library/dto/request/*.java`

### 教学要点
- Spring Boot 3.x 要求 JDK 17+
- Spring Boot 2.x 支持 JDK 8/11
- `jakarta.*` 是 Java EE 新的包名（Jakarta EE），`javax.*` 是旧名称

## 问题三：Flyway SQLite 依赖在阿里云镜像不存在

### 错误信息
```
[ERROR] Could not find artifact org.flywaydb:flyway-sqlite:jar:9.22.3 in nexus
(http://maven.aliyun.com/nexus/content/groups/public/)
```

### 原因分析
1. 阿里云 Maven 镜像不包含所有第三方库
2. `flyway-sqlite` 是 Flyway Teams 的商业功能

### 解决方案
移除 `flyway-sqlite` 依赖，仅使用 `flyway-core`：
```xml
<!-- Flyway -->
<dependency>
    <groupId>org.flywaydb</groupId>
    <artifactId>flyway-core</artifactId>
</dependency>
```

### 教学要点
1. 国内使用阿里云镜像时，某些依赖可能不存在
2. 可以尝试：
   - 使用中央仓库 `https://repo1.maven.org/maven2/`
   - 寻找替代依赖
   - 使用不依赖插件的版本

## 问题四：包名迁移 jakarta → javax

### 背景
当从 Spring Boot 3.x 降级到 2.x 时，需要进行包名迁移。

### 修改内容对照表

| 原包名 (Spring Boot 3.x) | 新包名 (Spring Boot 2.x) |
|------------------------|------------------------|
| jakarta.persistence.* | javax.persistence.* |
| jakarta.validation.* | javax.validation.* |
| jakarta.annotation.* | javax.annotation.* |

### 需要修改的文件
```
backend/src/main/java/com/example/library/entity/Book.java
backend/src/main/java/com/example/library/entity/Category.java
backend/src/main/java/com/example/library/entity/StockLog.java
backend/src/main/java/com/example/library/dto/request/BookRequest.java
backend/src/main/java/com/example/library/dto/request/CategoryRequest.java
backend/src/main/java/com/example/library/dto/request/StockOperationRequest.java
```

### 修改示例

**Entity 类修改：**
```java
// 从
import jakarta.persistence.*;

// 改为
import javax.persistence.*;
```

**DTO 类修改：**
```java
// 从
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.Min;

// 改为
import javax.validation.constraints.NotBlank;
import javax.validation.constraints.NotNull;
import javax.validation.constraints.Min;
```

### 教学要点
1. Jakarta EE 是 Java EE 的继任者，包名从 `javax.*` 改为 `jakarta.*`
2. 这是一个历史性变更，发生在 Jakarta EE 9
3. 不同版本的框架需要使用对应的包名

```xml

    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>

    <version>2.7.18</version>

<properties>
    <java.version>8</java.version>
</properties>
```

**Java 代码：**
```java
import javax.persistence.*;
import javax.validation.constraints.*;
```

## 教学要点总结

### 1. 依赖管理
- Spring Boot Parent 管理了大量依赖版本
- 第三方数据库扩展可能需要手动指定版本
- 国内镜像可能缺少某些依赖包

### 2. 版本兼容性
| Spring Boot | JDK 版本 | 包命名空间 |
|-------------|----------|-----------|
| 3.x | 17+ | jakarta.* |
| 2.x | 8 / 11 | javax.* |

### 3. 问题排查思路
1. 仔细阅读错误信息
2. 检查环境配置（Java 版本、Maven 版本）
3. 查看依赖冲突
4. 参考 Spring Boot 官方文档的版本要求

### 4. Jakarta EE 历史
- Java EE 由 Oracle 管理
- 2017年移交给 Eclipse 基金会，更名为 Jakarta EE
- Jakarta EE 9 开始将包名从 `javax.*` 改为 `jakarta.*`
- Spring Boot 3.x 采用 Jakarta EE 9+ 规范

## 问题五：数据库目录不存在

### 错误信息
```
Unable to obtain connection from database: path to '/path/to/backend/data/library.db':
'/path/to/backend/data' does not exist
```

### 原因分析
SQLite 需要数据库文件的父目录存在，但不会自动创建目录结构。

### 解决方案
```bash
mkdir -p backend/data
```

### 教学要点
- SQLite 不会自动创建目录
- 首次运行前需要确保数据目录存在
- 建议将 `data/` 添加到 `.gitignore`

## 问题六：Hibernate 类型验证失败

### 错误信息
```
Schema-validation: wrong column type encountered in column [id] in table [book];
found [integer (Types#INTEGER)], but expecting [bigint (Types#BIGINT)]
```

### 原因分析
1. Flyway 脚本使用 `INTEGER PRIMARY KEY AUTOINCREMENT`（SQLite 标准）
2. Hibernate 对 JPA `Long` 类型期望 `BIGINT`
3. SQLite 使用动态类型系统，但 Hibernate 验证时检查类型名称

### 解决方案
修改 `application.yml`，禁用 DDL 验证：
```yaml
spring:
  jpa:
    hibernate:
      ddl-auto: none  # 使用 Flyway 管理，禁用自动验证
```

### 教学要点
- SQLite 的 `INTEGER` 可以存储任何整数值（包括 64 位）
- Flyway 负责 schema 管理，Hibernate 验证会产生冲突
- 使用 `ddl-auto: none` 让 Flyway 独占 schema 管理权

## 问题七：Maven 使用错误的 Java 版本

### 现象
```bash
mvn -version
# 显示 Java version: 1.8.0_231（但系统有 Java 17）
```

### 原因分析
- 系统 `JAVA_HOME` 环境变量指向 Java 8
- Maven 优先使用 `JAVA_HOME` 而非 `java` 命令的版本

### 解决方案
创建 `~/.mavenrc` 文件指定 Java 17：
```bash
echo 'JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home' > ~/.mavenrc
```

### 验证
```bash
mvn -version
# Java version: 17.0.17, vendor: Eclipse Adoptium
```

### 教学要点
- Maven 使用的 Java 版本由 `~/.mavenrc` 或 `JAVA_HOME` 决定
- `~/.mavenrc` 优先级高于环境变量
- 不同项目可能需要不同的 Java 版本

## 问题八：日期字段解析错误

### 错误信息
```
Could not extract column [9] from JDBC ResultSet [Error parsing date]
```

### 原因分析
1. SQLite 存储日期为字符串 `'YYYY-MM-DD'` 格式
2. Hibernate 的 SQLite 方言在读取 `LocalDate` 时解析失败
3. 列位置 9 对应 `publish_date` 字段

### 临时解决方案
- 避免查询 `publishDate` 字段
- 或使用 String 类型存储日期

### 长期解决方案
- 开发环境使用 H2 数据库
- 生产环境使用 MySQL/PostgreSQL

### 教学要点
- SQLite 不是完整的数据库，日期类型支持有限
- 需要考虑数据库选择对开发的影响

## 问题九：端口被占用

### 错误信息
```
Web server failed to start. Port 8080 was already in use.
```

### 解决方案
```bash
# 查找并杀死占用端口的进程
lsof -ti:8080 | xargs kill -9
```

### 教学要点
- 开发过程中经常需要重启服务
- 后台运行时记得记录进程 ID
